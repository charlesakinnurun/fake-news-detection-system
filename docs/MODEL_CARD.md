# Model card: fake-news classifier

This card documents a binary text classifier trained on the ISOT "Fake and Real
News" dataset. It follows the intent of the model-card literature (Mitchell et
al., 2019) and records the information a reviewer needs to decide whether the
model is appropriate for a given use.

- **Model version:** 1.0.0 (the artifact records the exact version at training
  time)
- **Artifact:** `artifacts/model.joblib` plus `artifacts/model_metadata.json`
- **Code:** `src/fake_news_detection/`; training entry point `scripts/train.py`
- **Evaluation report:** `reports/test_evaluation.md` (generated by
  `scripts/evaluate.py`), produced from the run recorded below
- **Training date and metrics:** see the table in [Evaluation](#evaluation) and
  the metadata JSON for the authoritative, machine-readable values

## Overview

The system classifies a news headline and/or article body as resembling the
`REAL` or `FAKE` examples in a labelled corpus. It is a **style and vocabulary
classifier**, not a fact-checker. Nothing in the pipeline retrieves sources,
cross-references claims, or verifies evidence.

The served prediction is the class with the highest calibrated probability after
applying a decision threshold tuned on the validation split. The positive class
for all reported binary metrics is `FAKE`.

## Intended use

- A portfolio / research demonstration of an end-to-end NLP classification
  system, including data validation, leakage control, evaluation and serving.
- Triaging or prioritising text for **human** review in a research setting.
- Teaching and experimentation with classical text-classification pipelines.
- Comparing model families on a well-known, deliberately artifact-rich corpus.

## Out-of-scope use

Do not use this model to:

- declare that a specific article, claim, person or publisher is truthful or
  deceptive;
- automatically censor, demote, label or sanction publishers or individuals;
- make consequential decisions (legal, financial, employment, immigration,
  moderation appeals) without independent verification and human review;
- detect misinformation in languages, regions, publishers or time periods that
  are not represented in the training data;
- infer intent. A `FAKE` classification does not mean the author intended to
  deceive.

The output is evidence about similarity to a labelled corpus, not evidence about
reality.

### Data preparation

1. **Ingestion and schema mapping.** Each source file supplies its label; a
   configurable column map normalises source-specific names. Encoding problems
   are detected and reported.
2. **Validation.** Empty content, short bodies, malformed labels, over-long
   documents and conflicting labels are excluded or resolved according to
   `configs/data.yaml`. Every exclusion is counted and reported; nothing is
   dropped silently.
3. **De-duplication and clustering.** Exact duplicate texts are removed. The
   remaining documents are clustered with MinHash + LSH over word shingles
   (Jaccard threshold 0.80), so near-duplicates share a `dup_cluster` id.
4. **Leakage-safe split.** A stratified, *grouped* 70/15/15 split assigns every
   duplicate cluster to exactly one split. An audit in the dataset manifest
   verifies that no cluster or exact-match key appears in more than one split.
5. **Vectorisation.** Word TF-IDF is fitted inside the pipeline on the training
   split only. Character n-grams are configurable and disabled by default.

### Known dataset artifacts

The quality report (`reports/data_quality_report.md`) documents several
shortcuts that a classifier can learn:

- **Reuters wire marker.** 99.82% of `REAL` rows contain the Reuters wire marker,
  versus 1.31% of `FAKE` rows. A bag-of-words model can learn this marker
  instead of learning news credibility.
- **Disjoint subject vocabularies.** The `FAKE` and `REAL` subsets use entirely
  disjoint `subject` values (`politicsNews`/`worldnews` versus `News`,
  `politics`, `left-news`, etc.). Subject alone would separate the classes.
- **Body-presence imbalance.** 2.68% of `FAKE` rows have an empty body; no
  `REAL` row does. Body-less rows are excluded rather than allowed to become a
  label signal.
- **Publisher and time coverage.** `REAL` rows are Reuters newswire; `FAKE` rows
  come from a small set of outlets. Dates cluster in 2015–2017, and many rows
  have missing/unparsable dates.

These artifacts explain why in-distribution accuracy is very high and why it
must not be read as generalisation to new publishers or topics.

## Model and features

The pipeline is a single serialised scikit-learn `Pipeline`, so the preprocessing
used at inference is exactly the preprocessing used at training:

`TextCombiner` → TF-IDF (word 1–2 grams, optional character 3–5 grams) →
optional univariate selection → classifier.

Candidates compared on the validation split:

| Candidate | Role |
|---|---|
| `DummyClassifier` (prior) | Reference floor; confirms the metrics are not trivially achievable |
| Logistic Regression | Strong, fast, interpretable linear baseline |
| Complement Naive Bayes | Cheap sparse-text baseline |
| Random Forest | Non-linear comparison; expected to be slower and not necessarily better on sparse TF-IDF |
| Calibrated Linear SVC | Usually the strongest linear learner on this corpus; calibrated with an internal CV on the training split |

Model selection uses **validation macro-F1**, with ties broken by positive-class
F1, p95 latency and artifact size. The test split is not involved in any choice.
The comparison table is written to `reports/training_report.md` and
`reports/model_selection.json`.

## Evaluation

The test split is evaluated once, after the model, calibration method and
threshold have been frozen. The full numbers, confusion matrices, calibration
bins, latency measurements and error slices are in
`reports/test_evaluation.md` and `reports/test_evaluation.json`.

### Calibration

- The base classifier is calibrated with **isotonic regression** fitted on the
  validation split (the calibrated Linear SVC also uses internal cross-validation
  on the training split).
- The decision threshold is tuned on the validation split to maximise
  positive-class F1.
- Calibration diagnostics (Brier score, log loss, expected calibration error,
  reliability diagram) are reported on the test split.
- Because the calibrator and the threshold both see the validation split, the
  validation numbers are slightly optimistic; the test numbers are the honest
  estimate.
- A calibrated probability estimates how often documents with that score belong
  to the class **in the evaluation distribution**. It is not the probability that
  an article is objectively true or false.

### Error analysis

The evaluation script reports accuracy by subject bucket, document-length
quintile and model-confidence bucket, plus the most confident false positives and
false negatives. Slices with fewer than 30 documents are marked unreliable.
Headlines only are retained in the report; full article bodies are not copied
into diagnostics.

## Limitations and risks

1. **Superficial correlation.** The model can learn publisher style, wire
   markers, topic vocabulary and formatting rather than factual correctness.
2. **Distribution shift.** New publishers, topics, languages, time periods or
   writing styles can invalidate the learned associations. There is no
   out-of-distribution detector in version 1.0.0.
3. **Label noise.** `REAL`/`FAKE` labels come from the dataset, not from
   adjudicated ground truth. Some labels may be debatable or wrong.
4. **No source or temporal generalisation evidence.** The default split is
   random but duplicate-grouped, not source-held-out or temporal. It measures
   in-distribution performance.
5. **English-only.** The vectorizer and training corpus are English.
6. **Confidence is not verification.** A high score is not independent evidence
   of truth or deception.
7. **Short input.** Very short inputs provide little signal; headline-only
   classifications should be treated as especially weak.
8. **Operational trust.** Loading a joblib artifact executes pickle code. Only
   load artifacts produced by this repository and stored in a trusted location.

## Human review requirements

- Any real-world use must place a human reviewer between the model output and a
  consequential action.
- Reviewers should see the disclaimers, the model version, the threshold and the
  class probabilities, and should be able to override the prediction.
- Reports should describe the result as a model classification, not as a
  fact-check verdict.

## Maintenance and update recommendations

- Re-run `prepare_data.py` and inspect the quality report whenever the corpus or
  configuration changes.
- Keep the dataset fingerprint, seed, package versions and artifact checksum in
  the metadata; the training script records them automatically.
- Re-evaluate on a source-held-out and a temporal split before claiming
  generalisation.
- Version models with a monotonically increasing `model_version` in
  `configs/training.yaml`; retain the previous artifact for rollback.
- Recalibrate after any retraining or threshold change.
- Add drift monitoring on input length, vocabulary and predicted-class
  distribution before any production deployment.

## Ethical considerations

The system should support investigation and review, not replace professional
fact-checking. It should not be used to accuse individuals of deliberate
deception or to automate censorship. Any deployment should document its
decisions, provide an appeal path, and monitor for disparate error rates across
publishers and topics.
